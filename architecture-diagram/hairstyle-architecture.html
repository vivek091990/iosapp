How HairStyle works

One SwiftUI screen picks a photo, a preset and a coverage level, then sends them to a small FastAPI server. The server stamps a "HairStyle Preview" watermark on the photo, caches the result, and returns a PNG that the app shows in a before/after slider.

SwiftUI · iOS 16 PhotosPicker HTTP multipart → PNG FastAPI · Pillow · uvicorn

The system on one page

One preview, step by step

  1. You

    Pick a photo in the PhotosPicker. onChange loads it as Data, builds a UIImage, sets originalImage, and clears any old preview.

  2. You

    Choose a preset (Crown, Hairline or Part) and drag coverage. Both are plain @State; nothing is sent yet.

  3. ContentView

    Tapping Preview (Free) sets isLoading and calls PreviewService.preview(image:preset:coverage:) inside a Task.

  4. PreviewService

    Re-encodes the photo as PNG and writes a multipart body with a random boundary: fields preset and coverage, then file as photo.png.

  5. Network

    URLSession POSTs to Config.apiBaseURL + /v1/preview, which is http://localhost:8000 today.

  6. FastAPI

    Reads the upload and hashes it with the preset and the coverage bucket (coverage ÷ 10, so 40 and 49 share a result).

  7. Cache / Pillow

    On a hit, returns the stored PNG. On a miss, draws the tiled watermark over the photo, stores the bytes under the key, and returns them as image/png.

  8. ContentView

    A 2xx response becomes previewImage; any failure becomes errorMessage in red. With both images set, BeforeAfterSlider appears.

What to know before explaining it

  • No hairstyle is generated yet. Preset and coverage only change the cache key; the server returns the same photo with a watermark. This is the slot where a real model would go.
  • Every preview currently fails on the server. _add_watermark calls ImageDraw.textsize, which Pillow 10 removed, so the unpinned install returns a 500.
  • The Swift builder may not compile. MultipartFormDataBuilder chains mutating methods on a temporary value.
  • localhost only works in the simulator. On a real iPhone, Config.apiBaseURL must point at the Mac's LAN address or a hosted server.
Drawn from the code on main as of 25 Nov 2026. Fixes for the caveats above are being handled separately.
